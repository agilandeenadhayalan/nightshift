# Contributor checks

Use the actual GitHub issue numbers in `github/import_map.json`. Work in dependency order; an implemented test fixture does not satisfy provider, business, release or physical-device acceptance criteria. Keep unfinished gates in `docs/Issue_Status.md`.

Use a `codex/` branch and a focused PR. The FA-001 scope PR is separate; the first Android integration is stacked on that scope because the owner requested continued independent implementation while decisions remain pending. Do not close an issue on partial evidence.

Local supported versions: Node 24.13.0, npm 11.6.2 (root `packageManager`), Turborepo 2.11.13, Flutter 3.27.4 (Dart 3.6.2), JDK 17 or the compatible Android Studio JBR, PostgreSQL 17.7 and Redis 7.4.7. Commit the root npm lockfile and Flutter lockfile. Keep SQLite files, local databases, provider credentials, environment files, task caches and generated builds out of Git.

From the root run `npm ci`, `npm run check:repo`, `npm run typecheck`, `npm run build`, `npm test`, `npm run test:integration` and `npm run test:economics` (Python required). `npm test` includes backend-domain/API unit tests and the browser reference; `npm run test:audio` also runs that reference directly. `check:repo` includes contract drift checks, secret/boundary checks and the tooling regression tests. Integration tests require a dedicated PostgreSQL database and Redis instance; never point them at production. See the [setup runbook](Local_Development.md) for configuration.

On Windows run `npm run check:client`, `npm run check:mobile` and `npm run build:android` with Flutter on `PATH` and Java 17+ available for the generator. The Android command builds an ARM64 debug APK. Direct `flutter pub get`, `flutter analyze`, `flutter test` and `flutter build apk --debug` in `apps/mobile` remain available for a universal debug build. Keep Windows and WSL dependency installs separate; do not mutate the same `node_modules` concurrently.

For API changes, update the contract source, regenerate its JSON with `npm run generate --workspace @nightshift/contracts`, then run `npm run generate:client`. Commit the schema, generated SDK and consuming code together. `npm run check:client` reproduces generation with a checksum-pinned official generator and fails on changed, missing or extra generated files. Templates contain the reviewed diagnostics/validation customizations; change templates rather than generated files. The Android CI job runs this exact comparison before building. See `packages/contracts/README.md` for supported validation and tooling limits.

Follow the [monorepo rules](Monorepo.md): declare package dependencies, import public package entry points, keep apps independent and leave server financial rules in backend-domain. Reserved application directories become workspaces only when implemented. Turbo orders builds and can cache deterministic TypeScript outputs/checks; tests, Flutter operations and database/service tasks always execute uncached. A cache hit is not fresh integration-test evidence. Inspect the graph after changing package relationships and verify the API container when its runtime dependency closure changes.

The `validation` workflow runs these checks with isolated services. The secret guard includes a deliberate synthetic forbidden-key test, proving the checker recognizes a failing input before restoring a clean checkout. `npm audit --audit-level=high` rejects known high/critical npm vulnerabilities. Neither check proves the absence of every secret or security defect.

Repository owner follow-up: if the GitHub plan supports rulesets for this private repository, require the `backend` and `android` checks and a review on the default branch, block force pushes, and enable GitHub secret scanning where available. We do not claim branch protection is configured or available on the current plan. A green debug build is not a release approval.
