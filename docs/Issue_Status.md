# FA issue implementation and evidence register

Audit date: 20 November 2026. Source: all 64 specifications in `github/issues.json`, individual FA files, `github/import_map.json`, master plan, engineering contracts and the existing `audio/` code. All 64 GitHub issues were confirmed open during this implementation run. This is an engineering evidence register, not a request to close every issue.

The first unblocked issue is [#1](https://github.com/agilandeenadhayalan/nightshift/issues/1). Its scope and decision records are the starting deliverable. Foundation work follows #4, then #5/#6/#7 and #8. The first call path then uses test substitutes for unresolved production identity/review dependencies while implementing the shared #10/#15/#17/#18/#21/#22/#23/#25–#31 mechanisms. These substitutes do not satisfy the full production acceptance criteria for OTP, listener verification, provider callbacks, media cutoff or financial systems.

Status meanings:

- **Documented**: a reviewable document exists; required external approvals may remain.
- **Engineering verified**: the issue's engineering acceptance and verification checks have recorded evidence. Upstream owner decisions and PR review/merge status remain separate; this label does not close the GitHub issue.
- **Implemented subset**: code/configuration exists for the test-credit slice. Only the run's recorded checks establish verification; the full issue remains open where listed criteria or dependencies are unmet.
- **Pending**: required work or evidence is not yet delivered. A foundation or placeholder is not completion.
- **Deferred by dependency**: expansion is not activated before the required release gates.

No real-device result, store approval, production safety coverage, financial approval or provider account is inferred from a passing automated test. See `Decision_Register.md` and `Two_Phone_Test.md`.

## Evidence boundaries

The browser reference is a single-pair SQLite implementation, separate from the Android NestJS/PostgreSQL app. Preserving its tests is a regression check; it does not verify Android permissions, Agora audio, multi-device identity, production metering or payouts.

The latest authentication foundation continuation passed **209 tests**: 39 API units/provider tests, 5 shared domain tests, 60 PostgreSQL/Redis integration/schema/HTTP tests, 82 Flutter tests, 10 economics tests, 3 browser-reference tests and 10 tooling tests. Generated-client drift checks, static analysis, container startup, a real generated-Dart HTTP call/history journey and an ARM64 debug build also passed. See `FA009_Identity_Validation.md` for current evidence and remaining identity work; earlier foundation and WSL HTTP/restart results remain in `FA007_Verification.md` and `Verification.md`. Provider tests use synthetic transport, backend tests use synthetic readiness and Flutter tests substitute media interfaces; these do not prove real SMS delivery or audible media.

Universal and ARM64 debug APKs built successfully using existing Android SDK/NDK license coverage; no license acceptance was performed during this run. If future tooling requires additional licenses, the owner must review and accept them. The later 20 November physical run verified the partial flow and durable histories on two phones, as recorded in `Device_Debug_2026-11-20.md`. Owner-controlled Agora configuration was still absent, so the audible two-phone milestone remains unverified and incomplete.
