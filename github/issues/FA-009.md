# FA-009 — Implement phone authentication with abuse controls

Phase: **P1** · Area: **security** · Size: **M** · Release: **android-audio-mvp**

## Outcome

Authenticate through the owner-selected Firebase paid Phone Authentication service and use server-verified Firebase ID tokens for API sessions.

## Dependencies

FA-006, FA-007, FA-008

## Acceptance criteria

- [ ] Verify token issuer, audience, signature, expiry, revocation and phone-provider claims
- [ ] Consent, app admission/resend/rate controls, provider quota limits and error UX are explicit; app admissions do not cap direct Firebase SDK SMS billing
- [ ] Never log OTPs or full phone numbers and record provider consent

- [ ] Verify native Firebase phone proof on the server, bind the opaque Firebase UID and canonical verified phone to one app account, and reject mismatched/stale proof and unauthorized replay without bypassing existing revocation/deletion restrictions; exact consumed-proof retries remain idempotent.

Owner amendment, 20 November 2026 (D17): Firebase paid SMS to India (+91) supersedes the earlier Twilio/MSG91 selection and the required MSG91 challenge/custom-token exchange. The legacy MSG91 adapter remains optional compatibility code with separate prerequisites. This does not establish branded SMS delivery or approve production access.

## Verification

- [ ] Test expired/invalid tokens and wrong/expired OTP UX
- [ ] Verify repeated requests respect app limits, distinguish provider limits from admissions, and test bypass cannot enable production access
- [ ] Verify canonical binding, consumed-proof retries, cross-provider restrictions and logout/revocation without creating duplicate accounts

## Evidence and remaining acceptance

The owner confirmed both phones reached Customer after sign-in, and the isolated server recorded two verified phone identities and completed adult onboardings. That evidence does not distinguish manual SMS entry from automatic verification. Record actual sender/brand presentation, real-device wrong/expired-code recovery and refresh/revocation separately; never infer them from fixture tests or an app admission. The approved 1,000 SMS/day maximum and ₹5,000/month operating budget are separate limits; alerts are not an automatic billing cutoff. See `docs/Firebase_Development_Setup.md` and `docs/Account_Application_Verification.md`. This amendment closes no acceptance item or issue.
